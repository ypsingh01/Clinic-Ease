ClinicEase - Appointment Booking Platform
Requirement Analysis & SDLC Documentation
Project Type: Single Clinic, Multi-Doctor (5-6 doctors) Appointment Booking System
Roles: Patient, Doctor, Admin Stack: React (frontend), Node.js/Express (backend),
PostgreSQL (database) Notifications: In-app + WhatsApp Payments: Razorpay (pay-at-
booking) Deployment: Deferred (build-first approach)
SDLC PHASE 1: REQUIREMENT ANALYSIS
1.1 Purpose
ClinicEase digitizes appointment scheduling for a clinic with 5-6 doctors, replacing
manual/phone-based booking with a self-serve online system that reduces admin
workload, prevents double-booking, and keeps patients informed automatically.
1.2 Stakeholders
Stakeholder Interest
Patient Book/manage appointments easily, get reminders
Doctor Control availability, see daily patient load
Admin/Reception Oversee all bookings, handle walk-ins/edge cases, view revenue
Clinic Owner (client) Reduced no-shows, less phone workload, professional online presence
1.3 Functional Requirements (By Role)
Patient
« FRI: Register/login via email + phone (OTP verification for WhatsApp linkage)
» FR2: View list of doctors with specialty, photo, available days
« FR3: View real-time available hourly booking blocks for a chosen doctor/date (not
exclusive single-patient slots)
« FR4:Book into an hourly block and receive a token number with an estimated
consultation time, then pay online
« FRS5: Receive booking confirmation with token number and estimated time (in-app +
WhatsApp)
« FR6:Reschedule or cancel an upcoming appointment (within policy window)
« FR7:View appointment history and past prescriptions/notes (optional v2)
« FR8: Receive automated reminders (24h and 1h before estimated time)
